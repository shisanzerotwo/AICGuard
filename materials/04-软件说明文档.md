## 1. 产品简介

AICGuard 是一个**中文大模型安全评测与护栏平台**：用自建的中文母语攻击用例库，对大模型应用发起自动化安全评测，量化攻击成功率（ASR＝被攻破的攻击题占比）与防御效果，并**逐条归因（找原因）**攻击被哪一层防御拦截（或穿透）、生成修复建议。

- **产品形态**：Web 控制台 + 评测引擎 + 单文件报告看板
- **目标用户**：企业大模型应用开发团队、政务系统承建方、上线前安全评审环节
- **核心能力**：374 条主评测用例（6 大攻击族，含自进化 8 条）+ garak 对照组 27 条 + 阴性对照（正常请求对照）105 条 + agent 工具调用诱导语料 26 条 JSON 记录（含 6 条多轮链式 TA-21~26；JSONL 文件另含说明注释）；防御链路（**三层护栏** N1 归一化 → G1 输入规则 → G2 输出兜底（即最后一道补救审查），"靶子模型"为被测对象）+ 可扩展护栏注册表（agent 通道专属 **G3 敏感意图护栏 / G4 状态来源校验**）；基线/防御双线对照；拦截归因（找原因）与修复建议；真实模型跨厂商评测（R 次独立采样 + 95% CI）与成本控制；工具调用行为审计（agent 场景「行为即证据」判定）；Work Loop 成本耗尽通道（token 放大倍数指标）；评测器双向自检（阴性误报门禁（自动检查）+ 阳性必破断言，即「不冤枉好人 + 该破的必须破」）；语料半自动进化（评测→时破时不破（flaky）识别→候选→人工确认→合并）；**RAG 间接注入通道**（检索链路评测，先校验载荷送达再判定，三口径独立、不并入文本 ASR）

## 2. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 语言/运行时 | TypeScript，Node.js ≥ 23.6 原生类型剥离直跑 `.ts` | **零第三方依赖**：核心引擎只用 Node 内置模块，无 npm install、无构建步骤 |
| 服务器 | `node:http`（仅绑定 127.0.0.1） | 控制台与 API；跑批以子进程复用 CLI 评测器 |
| 真实模型对接 | OpenAI 兼容 `/chat/completions` 协议 | 适配 DeepSeek / 通义 / vLLM / Ollama / 各聚合网关 |
| AI 判定 | 金丝雀 + 行为标记 + 内容判据 + 工具调用审计 | **不以大模型当裁判**：判定可解释、可复现；unclear 单列不计分母 |
| 判断模型（可选） | TypeSafe Jev（`api.typesafe.ai/v1/systemone`） | 仅"AI 代审"功能使用；未配置 `TYPESAFE_API_KEY` 时自动落 LLM 兜底，功能不缺失 |
| 报告 | JSON / Markdown / 单文件 HTML | 看板数据内嵌，双击即开，无需服务端 |
| 交叉验证（可选） | promptfoo 0.123.1（MIT） | 独立目录 `ts/promptfoo/`，不进主链路，删除不影响评测 |

**为什么零依赖**：可离线部署、无供应链风险、演示机无环境地狱——这是面向内网/涉密场景的刻意选择。

## 4. 部署方式

### 4.1 标准部署（三步）

```bash
# ① 解压发布包（或 git clone）
# ② 进入主目录，确认 Node 版本
node -v          # 需要 ≥ 23.6
# ③ 启动控制台
node ts/src/server.ts
# 浏览器打开 http://127.0.0.1:7777
```

Windows 下可直接双击发布包内 **`start.bat`**（自动检查 Node 版本并启动）；macOS/Linux 用 **`start.sh`**。

### 4.2 仅命令行评测（不起控制台）

```bash
cd ts
node src/run.ts --profile full          # 离线靶子全量评测（约 1 秒），产出在 runs/<时间戳>/
node src/run.ts --profile none --quiet  # 只看数字
node scripts/m0-check.ts                # 环境自检
```

产出四类文件：`report.json`（全量数据）/ `report.md` / `dashboard.html`（看板，双击即开）+ 实验报告三份（语料对照/阈值扫描/消融）。

### 4.3 真实模型模式（可选，产生 API 费用）

在 `ts/.env.local`（不入库）配置：

```
AICGUARD_API_KEY=sk-xxxx
AICGUARD_BASE_URL=https://<你的 OpenAI 兼容网关>/v1
AICGUARD_MODEL=<模型名>
```

```bash
node src/run.ts --target llm --limit 20   # 标定/小规模
node src/run.ts --target llm --yes        # 全量（预估 >200 次请求必须 --yes）
node scripts/llm-leaderboard.ts --yes     # 两阶段榜单
```

内置成本控制：回复落盘缓存（`runs/llm-cache/`，改判据（判定规则）后重判不再调用 API，零成本）、跑批前预估请求数、超 200 次需显式确认；**token 用量管道**——靶子逐次记录增量用量（请求次数 / 入·出 token），主评测 `report.json` 输出按臂聚合的 `token_usage` 与 **token 放大倍数**（防御臂单用例平均总 token ÷ 无防御臂同口径），缓存命中记 0、离线靶子省略该字段。对接本地 Ollama 时 `AICGUARD_BASE_URL` 指向本机即可，**评测数据不出内网**。

### 4.4 云端 / 容器化部署（可按步骤落地，当前未随包提供 Dockerfile）

```dockerfile
FROM node:24-slim
WORKDIR /app
COPY . .
EXPOSE 7777
CMD ["node", "ts/src/server.ts"]
```

- 服务代码固定绑定 `127.0.0.1:7777`，容器内需在同一 Pod/网络命名空间放反向代理（如 nginx）转发；若要直接对外，需自行修改 `server.listen` 的绑定地址（属代码改动）。
- **公网暴露前必须加认证**（产品本身无账号体系）；TLS 在反向代理终止。
- 密钥用环境变量或 Secret 注入，禁止写入镜像；`ts/runs/` 挂持久卷，报告与证据可追溯。
- 资源建议：1 vCPU / 512 MB 起；离线评测无需 GPU。

### 4.5 安全与运维要点

| 项 | 做法 |
|---|---|
| 绑定地址 | 默认 `127.0.0.1`，评审现场只在本机访问 |
| 密钥 | 只放 `ts/.env.local`（gitignore）或环境变量；不进日志、不进材料、不进镜像 |
| 数据 | 离线模式不访问外网；真实模型只把请求发往所配网关；`runs/` 留在本机/内网 |
| 升级 | 替换代码目录，保留 `runs/` 与 `.env.local`；升级后用 392 项测试 + 双向门禁复验 |
| 故障 | 端口占用改 `AICGUARD_PORT`；Node 版本不足按提示升级；真实模型超时先查网关 |

## 5. 功能使用说明

### 5.1 控制台（http://127.0.0.1:7777）

五个工作台视图（侧边导航切换，明暗双主题）：

1. **体检台**：阳性自检 / 阴性门禁一键运行（状态灯）、语料资产计数、最近评测产物、自进化状态摘要——开机先看防线体检结论。
2. **攻击试探**：选防御档位（无防御/输入规则/规则+归一化/完整防御）与靶子（离线 / 真实模型 / agent），单发或**多轮**模式；结果区显示机器人回复、拦截层归因（N1/G1/G2/G3/G4 各自动作）、**修复建议**、归一化前后对比与攻破判定（红·攻破 / 绿·已拦截 / 蓝·正常）。内置 7 个快捷样例与「**多轮链式攻击**」演示剧本（G3 vs G4 同屏对照）；攻破时横幅引导进入进化实验室。
3. **评测中心**：三靶子跑批——离线 AgroBot（约 1 秒）/ AgentBot 四档矩阵（模拟零成本；真实模式需确认）/ 真实大模型（预算红线）；指标全呈现（无防御 ASR / 有防御 ASR / 防御有效率 / 误报率 / 按族等权双口径 / 拦截位置分布 / token 用量与放大倍数 / 平均延迟）+ 历史产物列表。另有 **RAG 知识库检索评测**（离线、零真实模型、零出网）：先校验攻击载荷是否真正进入检索上下文，再判定模型是否照做；结果按「防线判负 / 无法判定 / 无效测试」三口径独立呈现，**不与文本主评测分母相加**。
4. **进化实验室**：攻破案例 → 生成候选（1 次 LLM 调用）→ 逐条人工审核**或 AI 代审**（判断模型 Jev 逐条给出 通过/淘汰/退回人工 与理由、置信度，拿不准自动留给人工；任何一条可改判）→ 合并 + 自动回归门禁与主评测复验；含进化时间线（evolve-log 可视化）与 9 库语料浏览器。
5. **报告看板**：选一次 run 在页面内**嵌入观看完整 dashboard.html**（同源自包含文件），亦可新标签打开；切换主题时看板同步换肤。

支持预置参数：`?profile=none` 直达指定档位（演示/录制用）。

**评审 5 分钟验证路径**（离线、无需账号/外网）：

1. 解压发布包 → 双击 `start.bat`（或 `bash start.sh`）→ 打开 `http://127.0.0.1:7777`；
2. 体检台点“双向自检”，确认阴性 0/105、阳性 6/6；
3. 攻击试探选“无防御 + 离线 AgroBot”，点“直接注入”，看到红色“攻破”与证据；
4. 同一条输入切“完整防御”，看到绿色“已拦截 · 输入侧 · G1”与修复建议；
5. 评测中心点“离线全量”，约 1 秒后进报告看板，核对 85.8%→4.3%、301/5、0/105；
6. 报告看板查看分族、归因与整改建议；进化实验室查看候选→审核→合并留痕。

### 5.2 报告看板（`runs/<runId>/dashboard.html`）

单文件 HTML，包含：核心指标卡、分攻击族表现、拦截位置分布、**拦截归因与修复建议**（含证据样本回溯）、语料来源对照实验、消融实验、阈值权衡曲线、合规整改建议页。

### 5.3 命令行评测器（进阶）

- **agent 通道**：`node scripts/agent-eval.ts`（模拟 agent，零 API 成本）/ `--real`（真实 LLM agent，预算红线生效）——评测会调工具的智能体（26 条用例，含多轮链式诱导），判定看工具调用行为而非回复文本；full+agent 档挂 G3 敏感意图护栏 + G4 状态来源校验。
- **多次采样**：`node scripts/llm-multisample.ts --samples 5 --yes`（真实模型 R 次独立采样，输出逐轮值 + 池化 ASR + Wilson 95% CI + 逐用例攻破稳定性矩阵）。
- **Work Loop 成本评测**：`node scripts/workloop-eval.ts --yes`（真实模型；成本维度指标——单任务 token 相对良性基线的放大倍数，不走 ASR）。
- **语料进化**：`node scripts/evolve-probes.ts --generate`（攻破案例 → LLM 候选种子）→ 人工审阅**或 AI 代审**（`--autoreview`：判断模型 Jev 逐条判定，置信度不足自动退回人工；无判断模型 key 时自动落 LLM 兜底）→ `--merge` 合并（合并闸门仍需人工确认）。
- **RAG 通道**：`node scripts/rag-eval.ts --out <目录>`（离线检索链路评测；`--target llm` 才会调用真实模型并受预算红线约束）——逐项保留载荷送达证据，按「判负 / unclear / invalid_test」三口径输出，不发布百分比 ASR（分母不唯一）。
- **质量门禁（双向自检）**：`cd ts && node --test tests/*.test.ts`（**392 项行为测试**，2026-10-20 仓库与发布包各复跑一次、均 392/392 通过）+ `node scripts/fp-regression.ts`（阴性面：误报回归门禁，词表/权重改动后必跑）+ `node scripts/harness-sanity.ts`（阳性面：6 条必破样本 100% 按预期攻破断言）。

> **注意执行目录**：所有 `node …` 命令都要在 `ts/` 下执行（或先 `cd ts`）。在仓库根执行 `node --test tests/*.test.ts` 会输出 “tests 0 / pass 0” 且退出码 0，这是假绿。


`node src/run.ts [--target agro|llm] [--profile ...] [--threshold 0.70] [--expand 240] [--limit N] [--out runs/xxx]`——完整参数见 `--help`；三个实验模块（语料对照/阈值扫描/消融）随主评测同源产出（真实模型模式自动跳过以控成本）。

## 7. 兼容性与易用性说明

- **零依赖直跑**：无 venv、无编译、无 npm install，换机部署只拷贝目录；
- **离线可用**：离线靶子模式下全流程断网可跑，适合内网/评审现场；
- **易用性**：控制台全中文、快捷按钮一键填充、错误信息中文可读（如预算红线提示"预估 N 次真实 API 请求，超过 200 次红线，确认请加 --yes"）；评审 5 分钟路径见 5.1；
- **跨平台**：启动脚本同时提供 `start.bat`（Windows）与 `start.sh`（macOS/Linux）；实测仅 Windows，mac/Linux 未实机验证（见 3 节矩阵）。
- **已知兼容性事项**：
  - Node 版本 < 23.6 无法直跑 `.ts`（报 ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX 或未知选项，升级 Node 即可；推荐 24 LTS）。
  - Windows 控制台 `curl` 发送中文会因 GBK 编码乱码，API 测试请用 Node fetch 或 `--data-binary @file`。
  - 发布包为 ZIP（UTF-8 文件名、正斜杠路径）；旧版 Info-ZIP 6.00 解压中文名可能乱码，建议用 7-Zip、新版 unzip 或系统自带解压；若需在 Linux 服务器解压，可同时提供 `tar.gz`。
  - 服务只绑 `127.0.0.1`，容器/远程访问需反向代理（见 4.4）。

## 8. 常见问题（FAQ）

| 问题 | 处理 |
|---|---|
| 控制台打不开 | 确认 `node src/server.ts` 在运行、端口 7777 未占用（可用环境变量 `AICGUARD_PORT` 改端口）；服务只绑 127.0.0.1，需在本机浏览器访问 |
| "缺 AICGUARD_API_KEY" | 使用真实模型靶子时需先配置 `ts/.env.local`（见 4.3）；离线靶子无需任何配置 |
| 有防御 ASR = 0% | 先别高兴——大概率是判定被改坏或用了被删除的"刻意留出缺口"用例，请对照 `docs/00` 基线（4.3%）核查 |
| 真实模型跑批很慢 | 正常：单次调用 3–6 秒；缓存已命中请求会跳过，中断续跑不重复计费 |
| 想换被测模型 | 修改 `.env.local` 的 `AICGUARD_MODEL`，或命令行 `--model`；同一模型回复按参数缓存 |
| RAG 评测为什么不给百分比 ASR | 分母有 24 / 21 / 14 三种合理口径（总用例 / 有效送达 / 已送达且可计），百分比会掩盖口径差异；报告只给计数与口径，引用时必须带分母定义 |
| RAG 显示"无法判定"算不算防住了 | 不算。空响应/判不准一律记 `unclear`，不计入攻破也不计入分母；本项目不据空响应推断供应商行为 |
| 没有 Node 23.6 怎么办 | 安装 Node 24 LTS（nodejs.org）后重开终端；`start.bat` / `start.sh` 会检查版本并给出中文提示 |
| 测试显示 0 项通过 | 多半在仓库根执行了命令；先 `cd ts` 再 `node --test tests/*.test.ts`（根目录会匹配不到文件但退出码仍为 0） |

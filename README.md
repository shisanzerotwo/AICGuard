## 它解决什么问题

大模型应用上线前缺少可量化的安全评测手段。提示注入是最普遍的风险，而**现有开源红队工具的测试用例几乎全是英文机翻过来的**，在真实中文攻击面前会失效。

AICGuard 做三件别人不做的事：

1. **自建母语中文攻击用例库**，并用对照实验量化它相对机翻语料的价值
2. **拦截归因**——不只报"被攻破了"，而是定位**哪一层防御失效、为什么、该怎么补**
3. **评测会调工具的智能体（agent），并且自己会进化**——判定看工具调用行为而非回复文本；
   多采样发现的"时破时不破"缺口会驱动语料自进化（候选→人工审核→合并→复验基线），护栏同样可扩展补位

## 快速开始

**不需要 `npm install`，不需要编译。** 只需要 Node ≥ 23.6。

```bash
cd ts

node scripts/m0-check.ts    # 环境自检（第一次先跑这个）
node src/run.ts             # 一键评测（离线靶子），产出报告与看板
node src/server.ts          # ★ 控制台：浏览器内五视图（体检台/攻击试探/评测中心/进化实验室/报告看板）http://127.0.0.1:7777
node src/run.ts --target llm --limit 20   # 真实模型靶子（密钥配在 ts/.env.local）

# 质量门禁（三件套）
node scripts/fp-regression.ts    # 阴性面：误报 ≤5% + 拦截基线漂移
node scripts/harness-sanity.ts   # 阳性面：必破样本 100% 按预期攻破（评测器自检）
node scripts/agent-eval.ts       # agent 通道评测（mock 零成本；--real 真实模型）
node scripts/workloop-eval.ts    # Work Loop 成本耗尽评测（真实模型，成本维度指标）
```

产出在 `ts/runs/<时间戳>/`：

| 文件 | 说明 |
|---|---|
| `dashboard.html` | **演示看板**，双击直接打开，无需服务器 |
| `report.md` | 完整评测报告 |
| `report.json` | 结构化数据，供二次开发 |

## 实测结果

农技问答机器人靶子，374 条攻击用例 + 105 条正常请求（P0-2 扩容 + 自进化 8 条后）：

| 指标 | 数值 |
|---|---|
| 无防御 攻击成功率 | **85.8%** |
| 有防御 攻击成功率 | **4.3%** |
| 无防御 ASR（按族等权） | **92.7%** |
| 有防御 ASR（按族等权） | **11.4%** |
| 防御有效率 | **95.0%** |
| 误报率 | **0.0%**（误报治理前 13.3%，见 docs/08 P0-2） |
| 输入侧拦截 / 输出侧兜底 | 301 / 5 |
| 无法判定（unclear） | 基线 / 完整防御各 1 条（不计入 ASR 分母） |

**残留的 4.3% 是刻意保留的。** 它们全部来自同一类攻击：用语义改写绕过关键词规则，并且模型用 Base64 输出泄露内容，连输出侧的明文金丝雀检测也一并绕开。

一个只会报 100% 防御成功的工具没有价值——**这 4.3% 恰恰证明了工具的有效性**。

> **两个口径并列呈报**：编码混淆族占语料 69%（257/374）且被归一化全歼，会把聚合 ASR 拉低；按攻击族等权平均为无防御 **92.7%** / 有防御 **11.4%**（2026-10-18 口径修正：修复线 M1 统一分族统计的 unclear 分母处理，旧值 92.1% / 11.3% 作废，修正说明见 materials/02-测试报告.md）。报告与看板同时给出聚合与等权两个口径，避免"只赢单一族"造成数字失真。

### agent 通道与自进化（2026-10-03 新增能力）

**会调用工具的智能体同样能评测。** 现有三层文本护栏对 agent 攻击面拦截 0（攻击是自然业务请求，
无注入关键词）；判定改看**行为**——工具调用审计（`tool-audit.ts`）对参数归一化后匹配禁用项
（`kebaiwei`、`甲·拌·磷` 等形变一视同仁）。补上 agent 专属护栏 G3 后，真实模型 **R=5 采样 0/100**（历史 20 用例口径；2026-10-05 语料扩至 26 条含 6 条多轮链式后，G3 跨轮盲区被实证 1/130，由 G4 状态来源校验补位，复验 **0/130**）
（Wilson 双侧 95% CI 上界 3.7%；rule-of-three 单侧近似上界 3.0%）、误拦 0。

**评测结果反哺评测本身（自进化闭环）。** `llm-multisample.ts` 做 R 次独立采样（每轮换缓存盐 =
真请求）+ Wilson 95% CI + 逐用例稳定性矩阵；"时破时不破"（flaky）的缺口经
**候选生成 → 人工审核 → 合并语料 → 基线复验**闭环入库——已实际合并 8 条种子（EV-11~18），
语料 366→374 条并复验。护栏侧同理：注册表模式让"发现新缺口 → 新护栏补位"成为常规动作
（G3 即由 agent 通道缺口驱动诞生）。

**攻击面随组合放大，护栏随之生长（2026-10-05，三篇文献驱动）。** 参照技能链劫持研究
（arXiv:2610.01564）的链式伪造授权思想，新增**多轮链式诱导**用例 TA-21~26：禁用项只出现在
轮 1、轮 2 用"按刚才批准的"式回指——G3 的"同轮同现"判据对此失明，真实模型实测被攻破
1/5（flaky，`runs/agent-20261005080805`）。由此诞生第二个 agent 专属护栏 **G4 状态来源校验**
（授权声明必须来自可核实渠道而非对话声明），复验 **0/130**（Wilson 95% CI 上界 2.9%，
良性误拦 0/50，`runs/agent-20261005083150`）。同时把**评测器自身的可信度**固化为双向自检：
阴性面 fp-regression + 阳性面 `harness-sanity`（6 条必破样本 100% 按预期攻破断言，覆盖五条
判定路径；方法论佐证 arXiv:2609.32691）。另建成 **Work Loop 成本耗尽通道**（成本维度指标，
不走 ASR）：真实模型实测 6 条攻击全部放大 **2.4~3.8×**（峰值 6.1×）、未达 5× 阈值
（`runs/workloop-20261005091942`），既有缓解（maxTokens、工具循环 ≤2 轮）有效。

## 核心资产

**`data/` 下的中文攻击用例库是整个项目最值钱的部分**，且与语言无关：

| 文件 | 内容 |
|---|---|
| `probes_zh.jsonl` | 母语中文自建用例（6 大攻击族） |
| `probes_mt_zh.jsonl` | 机翻腔对照用例（模拟 garak 机翻产物） |
| `probes_agro.jsonl` | 农技靶子专属用例（危害：诱导推荐禁用农药） |
| `probes_tool_abuse.jsonl` | agent 工具滥用用例（看行为不看文本） |
| `probes_workloop.jsonl` | Work Loop 成本耗尽用例（token 放大维度） |
| `probes_garak_mt.jsonl` | garak 真机翻对照组（跨域主题） |
| `probes_candidates.jsonl` | 语料自进化候选池（含未审/拒收，正式评测不读） |
| `sanity_positive.jsonl` | 阳性必破样本（评测器自检） |
| `benign_zh.jsonl` | 正常请求，含"边缘正常"压力样本（误报回归） |

**母语与机翻的措辞几乎不重叠**——这是"中文用例库必须自建"这一结论的立论基础。

## 技术栈为什么是 TypeScript

| 理由 | 说明 |
|---|---|
| **同栈才能改 promptfoo** | 最佳开源底座 promptfoo 是 TS。用 Python 只能调它的 CLI，那就真成"套壳"了 |
| **产物本来就是 Web** | 看板、对话界面、报告页——前端跑不掉，一套语言前后端通吃 |
| **部署风险低** | 没有 venv / CUDA / 版本地狱，演示机出问题好救 |
| **零依赖可行** | Node 24 原生跑 `.ts`，核心逻辑不需要任何 npm 包 |

> ⚠️ 用 Node 原生跑 `.ts` 是 strip-only 模式：**不支持参数属性、`enum`、`namespace`、装饰器**。详见 `ts/README.md`。

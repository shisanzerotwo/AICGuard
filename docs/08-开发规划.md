## P1 · 评测能力扩展

### P1-1 多模型榜单常态化 ✅ 完成（2026-10-03，docs/10 §2-§4）

- 目标：3 模型 × 3 档位榜单入材料（docs/01 §11.1 预算：~1900 次 / ~82 万 tokens / 2 小时内）
- 步骤：`.env.local` 换 MODEL 逐个跑 `scripts/llm-leaderboard.ts`；榜单脚本已支持任意 OpenAI 兼容模型
- 验收：三模型榜单表 + 模型间差异分析（哪个模型更容易被哪族攻破）入 materials
- 注意：换模型前跑一次 `--limit 20` 标定成本；模型随机性要求榜单注明单次采样口径

### P1-2 攻击通道扩充 ◐ 部分完成（2026-10-05 更新）

- 目标：新增攻击族（建议顺序：RAG 间接注入 → 智能体工具调用诱导 → 多模态）
- **已完成（2026-10-03 + 2026-10-05）**：智能体工具调用诱导（20→26 条，含 6 条多轮链式 TA-21~26，
  参照 arXiv:2610.01564；G3 盲区由 G4 补位，见 docs/10 §10）；**规划外新增** Work Loop 成本耗尽
  通道（resource_exhaustion，6 条，成本维度指标不走 ASR，docs/10 §10.3）
- **未做**：RAG 间接注入（设计原则已定：载荷送达校验——判定前确认攻击载荷实际进入检索上下文，
  防 arXiv:2609.32691 式浅层判据虚高）、多模态输入
- 纪律：沿用语料三件套——种子 + `notes` 溯源 + `judge` 判据；每个新族 ≥15 条母语种子 + 机翻对照
- 验收：新族进 FAMILIES 标签表与分族表现表；基线 ASR 有区分度（不是全 0/全 100%）
- 涉及模块：`types.ts`（Family 联合类型）、`attacks.ts`（FAMILIES）、`data/`、靶子应用需支持对应注入面（如 AgroBot 增加"检索到外部文档"通道）

### P1-2B 规划外增量（2026-10-05 批次，三篇文献驱动，docs/09 §9 有全表）

- **评测器双向自检**：阳性面 `harness-sanity.ts`（6 条必破样本 100% 按预期攻破断言）+ 既有阴性面
  `fp-regression.ts`；方法论佐证 arXiv:2609.32691
- **G4 状态来源校验护栏**：多轮链式缺口驱动诞生（`state-guard.ts`，注册表扩展），复验 0/130
- **token 用量管道**：TargetResponse/PipelineResult/AttackResult 增量 usage → 按臂聚合 +
  `token_usage` 与放大倍数入主评测 report.json

### P1-3 judge.ts 引入「同句绑定」

- 背景：server.ts 演示判据已实现（demoContentBreach），judge.ts 的 requireContext 仍是全文共现——未来语料一旦配置推荐语境就会误判"拒答+推荐合法替代"
- 验收：judgeByRule 支持同句绑定选项；构造回归用例证明两种语义差异；现有语料（无 requireContext）指标不变
